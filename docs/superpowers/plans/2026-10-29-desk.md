# «Мои сделки» (personal trading desk) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A section of the admin, for the owner only, that prices a trader's inventory, records
personal deals, sends the Skinslink deposit offer, tracks stock sold by hand, and shows the
owner's own profit in USD — apart from the shop's numbers.

**Architecture:** A new backend module `desk` with its own tables (`desk_deals`, `desk_items`,
`desk_deposits`, `desk_entries`, `desk_withdrawals`), routes under `/api/v1/admin/desk`, a
role `desk` on top of `admin`. Deposits reuse the Skinslink `DepositClient`; their state comes
from the existing Skinslink deposit webhook (routed by a `desk-` prefixed `merchant_tx_id`) and
a 60 s scheduler poll. Profit is an append-only `desk_entries` ledger (one signed USD row per
resolution or revert), so a period's profit is a sum over the window. Admin SPA:
`features/desk/`.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, Alembic, pytest + testcontainers + respx;
Vite + React 19 + TanStack Query, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-29-desk-design.md` (approved 2026-10-29).

## Global Constraints

- Every `/admin/desk/*` route requires `admin` **and** `desk` roles: 403 otherwise.
- Never read desk tables from `sales`, `wallet`, `analytics`, `orders/dashboard`, alerts or
  «Сверка»; never write desk data into the shop's wallet. The dashboard and
  `SkinslinkBalanceLow` keep showing the whole Skinslink balance (owner ruling).
- The shop's selling switches, limits and risk holds do **not** apply to desk deposits; only
  the Skinslink credentials are needed (`settings.skinslink_api_key`).
- Money: `Decimal`; USD stored to 6 places (`Numeric(18, 6)`), soʻm whole (`Numeric(18, 0)`),
  rates `Numeric(12, 4)`. Profit is always USD.
- Every write takes `Idempotency-Key` (≥ 16 chars, the existing `_replay` / `save_replay`
  pattern, as in `skins.admin_routes.patch_item`); `POST /admin/desk/inventory` is keyless (it
  writes nothing — say so in its docstring).
- No trade link, trader name or note in logs. Trade links are PII: `docs/security/pii-handling.md`.
- Deposit create (ADR-0016 rules): commit the deposit row as `creating` first, then one
  `create-deposit` call with nothing open across it; a lost answer is resolved by
  `deposit_status` under the same `merchant_tx_id`, never by sending again; `already_exists`
  (409) is adopted.
- Admin copy is Russian only. Pages work at phone width (16 px gutter, no horizontal scroll
  except inside tables).
- Coverage: add `desk` to the ≥ 95 % module list (`scripts/check-module-coverage.py`, its test,
  AGENTS §9).

## Review Focus

1. A `create-deposit` that times out → the deposit stays `creating`, the poll finds it by
   `merchant_tx_id`; a second «Отправить обмен» on the same items is refused while a deposit is
   open (409 `deposit_open`). Pinned in Task 5.
2. A Skinslink webhook with a `desk-…` id queues no sale check, and a sale's UUID id never
   touches a desk deposit. Pinned in Task 5.
3. A revert after the credit → a negative entry dated on the revert day, the deal `reverted`,
   the Skinslink share drops; the earlier day's profit is unchanged. Pinned in Task 5.
4. A UZS price or sale without a rate → 422 `rate_required`; a rate ≤ 0 → 422. Pinned in Task 3.
5. An admin without `desk` → 403 on every desk route and no «Мои сделки» in the menu. Pinned in
   Tasks 1 and 6.

### Task 3: Money rules (pure)

**Files:**
- Create: `apps/api/src/csmarket/modules/desk/money.py`
- Test: `apps/api/tests/unit/test_desk_money.py` (with hypothesis)

**Interfaces — Produces:**
- `def to_usd(amount: Decimal, currency: Literal["UZS","USD"], rate: Decimal | None) -> Decimal` —
  USD as is; UZS ÷ rate, quantized to 0.000001 `ROUND_HALF_UP`. Raises
  `ValidationError(code="rate_required")` for UZS without a rate or with rate ≤ 0.
- `def split_cost(total_usd: Decimal, weights: Sequence[Decimal | None]) -> list[Decimal]` —
  weight = the item's `skinslink_usd`; a `None` weight takes the mean of the known weights (all
  `None` → equal shares); shares quantized to 0.000001, the last share takes the remainder so
  `sum == total_usd` exactly.
- `def split_revenue(amount_usd: Decimal, weights: Sequence[Decimal | None]) -> list[Decimal]` —
  the same rule (a deposit's credited amount over its items).

- `POST /inventory {trade_link}` → `{items: [{asset_id, name, image_url, price_usd}]}` — keyless;

  `steam_refused` + `reason`; other refusals / outage → 503 `desk_unavailable`; 422
  `trade_link_invalid`.
- `GET /rate` → `{usd_uzs: str | null}` (CBU, no uplift, from `fx.api.current_usd_uzs`).
- `POST /deals` (keyed) `{trader, note?, trade_link?, method, items: [{name, asset_id?, image_url?, skinslink_usd?, destination}] (1..200), paid_amount?, paid_currency?, rate?, paid_at?}` → `DealOut`.
  With a price, `paid_usd = to_usd(...)` and items' `cost_usd = split_cost(paid_usd, weights)`;
  status `paid` when `paid_amount` is given, else `agreed`.
- `PATCH /deals/{id}` (keyed) — any of `trader, note, method, status, paid_amount, paid_currency,
  rate, paid_at, guarantor_released: bool`. Setting or changing the price recomputes `paid_usd`
  and every **unresolved** item's `cost_usd` (resolved items keep theirs). A manual `status`
  is any of the six.
- `GET /deals?status=&q=&cursor=` → newest first, 50 per page, `q` matches trader (ILIKE).
- `GET /deals/{id}` → `DealOut`: the deal, items, deposits, `protected_until` (the latest
  credited/hold deposit's acceptance + 7 days, else `null`), `profit_usd` (sum of its entries),
  `resolved` (every item's state in `credited`,`sold`,`written_off`,`reverted`).
- `POST /items/{id}/sell` (keyed) `{where, amount, currency, rate?, at?}` — only a `stock`
  item in `open`: `sold_usd = to_usd`, state `sold`, entry `sale` with
  `profit_usd = sold_usd − cost_usd` at `at or now()`. 409 `item_not_open` otherwise.
- `POST /items/{id}/move` (keyed) `{destination}` — only `open` items.
- `POST /items/{id}/write-off` (keyed) `{note}` — `open` or `sent`→ no (409); entry `write_off`
  with `profit_usd = −cost_usd`.
- After any resolution, if every item is resolved and the deal is not `cancelled`/`reverted`,
  the deal becomes `closed` (`deals.close_if_done(db, deal)`).
- `GET /stock` → open `stock` items with cost, deal, trader.
- `POST /withdrawals` (keyed) `{amount_usd, note?}`; `GET /withdrawals`.
- `GET /summary?from=&to=` (Tashkent dates, default last 30 days) →
  `{profit_usd, revenue_usd, deals_closed, items_resolved, in_transit_usd, stock_usd, skinslink_share_usd}`:
  `profit_usd` = Σ `desk_entries.profit_usd` with `at` in the window; `in_transit_usd` = Σ cost of
  unresolved non-stock items of `paid`/`received` deals; `stock_usd` = Σ cost of open stock
  items; `skinslink_share_usd` = Σ all `revenue_usd` entries − Σ withdrawals (all time).
- Produces: `deals.close_if_done(db: AsyncSession, deal: DeskDeal) -> None`, `DealOut` schema.

**Interfaces — Produces:**
- `POST /deals/{id}/deposit` (keyed) → `DealOut`: takes the deal's `skinslink` items in `open`
  with an `asset_id`; 409 `nothing_to_send` if none, 409 `deposit_open` if a deposit of the deal
  is `creating`/`new`/`pending`/`active`, 409 `trade_link_missing`. Commits a `creating`
  deposit and marks the items `sent` with its id, then `create_deposit(merchant_tx_id=f"desk-{id}",
  partner, token, asset_ids, min_prices=sales.pricing.min_prices(...))` (import through
  `sales.api` — add the export). Refusals: a `PRICE_CODES` code → deposit `failed`, items back to
  `open`, 409 `prices_moved`; a Steam code → same, 409 `steam_refused` + `reason`; 409
  `already_exists` → adopt via `deposit_status`; outage → leave `creating`, answer 200 with
  the `DealOut` showing it (the poll resolves).
- `async def check_deposit(db: AsyncSession, client: DepositClient, *, deposit_id: str) -> None`
  — locks the row, asks `deposit_status(merchant_tx_id)`, applies:
  - `None` and `creating` older than 10 min → `failed`, items `open`.
  - `hold`/`completed` → deal `received` if it was `agreed`/`paid`.
  - `completed` with `amount_usd` and no `credited_at` → `credited_at = now()`, its items
    `credited`, entries `credit` per item with `revenue_usd = split_revenue(amount, weights)[i]`,
    `profit_usd = revenue − cost_usd`; then `close_if_done`.
  - `failed`/`canceled` → items back to `open`.
  - `reverted` after a credit → `reverted_at = now()`, items `reverted`, entries `revert` per
    item with `revenue_usd = −credited revenue`, `profit_usd = −credited revenue`; deal
    `reverted`. Before a credit → items `reverted`, deal `reverted`, no entries.
  - sets `next_check_at`: 1 min while live, 30 min in `hold`, never again when settled.
- `async def mark_due(db: AsyncSession, merchant_tx_id: object) -> bool` — sets
  `next_check_at = now()` for a known desk deposit; `False` for anything else.
- `async def poll_deposits(db_factory: SessionFactory, client: DepositClient) -> int` — every due
  deposit, one session each, one failure never stops the tick (as `sales.reconcile.poll_sales`).
