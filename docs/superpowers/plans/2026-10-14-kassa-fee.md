# Kassa Fee Paid by the Buyer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Click / Payme / Uzum add their own percent on top of an order or a top-up paid through
them; the buyer sees it on the tile and in the total.

**Architecture:** An admin-edited singleton document `payment_settings` holds a rate per kassa.
Every kassa attempt (`payments` row) freezes its `fee_pct` and `fee_uzs` when it is created;
`payments.amount_uzs` stays the base. One function, `kassa_charge(db, payable, provider)`, says
what a kassa must charge (the live attempt's frozen fee, else the current rate) and every
kassa-facing amount — the intent URL, Payme −31001, Click −2, Uzum `/check` and 10011 — uses it.
Settling, refunds and the ledger do not change.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, Alembic, Pydantic v2; Next.js 15 storefront; Vite
admin; Vitest; pytest (integration on CI).

**Spec:** `docs/superpowers/specs/2026-10-14-kassa-fee-design.md`

## Global Constraints

- Rate per kassa: decimal 0–10, two places; default 0 (no change until typed).
- `fee = ceil(base × pct / 100)` whole soʻm; the kassa charges `base + fee`.
- Fee on kassa-paid orders **and** top-ups; balance payment carries none; `mock` carries none.
- Refund to the balance = the price only (unchanged). A top-up reversal debits `topup.amount_uzs`
  (unchanged). The ledger is unchanged.
- The rate is frozen on the attempt at creation; a later admin change never moves it.
- No legal-document change. Money as `Decimal` / digit strings, never floats.
- Copy in ru / uz / en; kassa names never translated; no service meta in copy.
- Every state-changing endpoint takes `Idempotency-Key`; the settings save takes `If-Match`.
- Never log PII. `make gen-api` after the API changes; commit `docs/api/openapi.json` + client.

## Review Focus

1. A Payme / Uzum webhook arriving **before** the storefront opened an attempt (no live attempt) —
   the current rate must be used and then frozen by `ensure_attempt`, so check and create agree.
2. The admin changes a rate while a buyer sits on Payme's page — the kassa must still be accepted
   at the old total (frozen on the attempt), and refused at the new one.
3. A rate of 0 — totals, tiles and amounts must be byte-identical to today (no «0 %», no
   «Комиссия 0»).
4. A retried buyer switching kassas on one order (Click → Payme) — each attempt has its own fee.
5. Rounding at a fractional fee (1.5 % of 33 333 = 499.995 → 500) — web and API must agree.

```python
"""The kassa fee the buyer pays on top (spec 2026-10-14-kassa-fee).

Row 1 of ``payment_settings`` holds a percent per kassa; :func:`kassa_charge` is the one place
that says what a kassa must charge for a payable: the base plus the fee frozen on the live
attempt, or — before any attempt exists — the current rate (``ensure_attempt`` then freezes it).
No cache: one primary-key read per kassa call.
"""

from __future__ import annotations

import json
from dataclasses import dataclass
from decimal import ROUND_CEILING, Decimal

from pydantic import BaseModel, ConfigDict, Field, ValidationError
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

from csmarket.core.clock import now
from csmarket.core.logging import get_logger
from csmarket.modules.payments.models import Payment, PaymentSettingsRow
from csmarket.modules.payments.payable import Payable

log = get_logger("csmarket.payments.fees")

_PCT = Field(default=Decimal(0), ge=0, le=10, max_digits=4, decimal_places=2)
#: Attempt statuses a kassa may still charge (``hooks.LIVE``).
_LIVE = ("created", "pending")


class KassaFees(BaseModel):
    """The whole document, as stored in ``payment_settings.settings``."""

    model_config = ConfigDict(frozen=True)

    click: Decimal = _PCT
    payme: Decimal = _PCT
    uzum: Decimal = _PCT

    def pct(self, provider: str) -> Decimal:
        """The percent of ``provider``; 0 for the balance, ``mock`` and anything else."""
        return {"click": self.click, "payme": self.payme, "uzum": self.uzum}.get(
            provider, Decimal(0)
        )


DEFAULT_KASSA_FEES = KassaFees()


def fee_of(base: Decimal, pct: Decimal) -> Decimal:
    """``ceil(base × pct / 100)`` whole soʻm."""
    return (base * pct / 100).to_integral_value(rounding=ROUND_CEILING)


@dataclass(frozen=True)
class Charge:
    """What a kassa takes for a payable: the base, the fee and their sum, whole soʻm."""

    pct: Decimal
    fee_uzs: Decimal
    total_uzs: Decimal


async def settings_row(db: AsyncSession) -> PaymentSettingsRow | None:
    """Row 1, read fresh."""
    return await db.get(PaymentSettingsRow, 1, populate_existing=True)


async def read_kassa_fees(db: AsyncSession) -> KassaFees:
    """The saved document, or no fees at all."""
    row = await settings_row(db)
    if row is None:
        return DEFAULT_KASSA_FEES
    try:
        return KassaFees.model_validate(row.settings)
    except ValidationError:
        log.warning("payments.fees.row_invalid", reason="falling back to no fees")
        return DEFAULT_KASSA_FEES


async def save_kassa_fees(db: AsyncSession, *, fees: KassaFees, admin_id: str) -> None:
    """Upsert row 1; flushes, never commits. Open attempts keep their frozen fee."""
    document = json.loads(fees.model_dump_json())
    row = await settings_row(db)
    if row is None:
        db.add(PaymentSettingsRow(id=1, settings=document, updated_by=admin_id))
    else:
        row.settings, row.updated_by, row.updated_at = document, admin_id, now()
    await db.flush()


async def current_charge(db: AsyncSession, *, base: Decimal, provider: str) -> Charge:
    """The charge at today's rate — for a new attempt."""
    pct = (await read_kassa_fees(db)).pct(provider)
    fee = fee_of(base, pct)
    return Charge(pct=pct, fee_uzs=fee, total_uzs=base + fee)


async def kassa_charge(db: AsyncSession, payable: Payable, provider: str) -> Charge:
    """What ``provider`` must charge for ``payable``: the live attempt's frozen fee, else today's.

    ``payable`` is ``not_found``: the base is 0 and so is the fee (the caller refuses it anyway).
    """
    owner_id = payable.order.id if payable.order else payable.topup.id if payable.topup else None
    if owner_id is not None:
        owned = Payment.order_id if payable.kind == "order" else Payment.topup_id
        live = (
            await db.execute(
                select(Payment)
                .where(owned == owner_id, Payment.provider == provider, Payment.status.in_(_LIVE))
                .order_by(Payment.created_at.desc())
                .limit(1)
            )
        ).scalar_one_or_none()
        if live is not None:
            return Charge(pct=live.fee_pct, fee_uzs=live.fee_uzs, total_uzs=live.amount_uzs + live.fee_uzs)
    return await current_charge(db, base=payable.amount_uzs, provider=provider)


__all__ = [
    "DEFAULT_KASSA_FEES",
    "Charge",
    "KassaFees",
    "current_charge",
    "fee_of",
    "kassa_charge",
    "read_kassa_fees",
    "save_kassa_fees",
    "settings_row",
]
```
