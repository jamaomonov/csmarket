# P2P Top-up and Kassa Switches Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Balance top-ups by a card-to-card transfer, credited automatically from the HUMO bot's
Telegram notifications (through a relay shared with YuPay), and an on / maintenance / off switch
for every kassa.

**Architecture:** Kassa statuses join the kassa-fee document (`payment_settings`) and gate every
new payment on the server. A new module `p2p` (ported by allow-list from YuPay's `modules/p2p`)
owns cards, reservations, the notification journal and settings; P2P is a `p2p` gateway inside
the existing top-ups, so a matched transfer settles the top-up's payment through
`payments.hooks.settle` like any kassa. A Cloudflare Worker fans the bot's webhook out to YuPay
and csmarket.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, Alembic, PyNaCl (`core.crypto`), APScheduler,
Prometheus; Next.js 15 storefront; Vite admin; a Cloudflare Worker (plain JS, Vitest).

**Spec:** `docs/superpowers/specs/2026-10-19-p2p-topup-design.md`

## Review Focus

1. A transfer to YuPay's card (last4 not ours) must be `ignored`, never matched to a csmarket
   reservation of the same amount.
2. A late transfer (after `expires_at`, within quarantine) still pays its own reservation; after
   quarantine it is `unmatched` and never pays the next reservation of that amount.
3. The same Telegram update delivered twice (relay retry) credits once.
4. A kassa switched to maintenance while a payment is open: the webhook still settles it.
5. Manual credit of an unmatched transfer cannot run twice for one row, nor while a reservation
   of that card and amount is pending or quarantined.

KassaStatus = Literal["on", "maintenance", "off"]
#: Kassas that start switched off until the owner turns them on.
_OFF_BY_DEFAULT = frozenset({"p2p"})


class KassaFees(BaseModel):
    ...
    #: A kassa's switch; a missing key is ``on`` (``off`` for :data:`_OFF_BY_DEFAULT`).
    statuses: dict[str, KassaStatus] = Field(default_factory=dict)

    def status(self, provider: str) -> KassaStatus:

        default: KassaStatus = "off" if provider in _OFF_BY_DEFAULT else "on"

`switches.py`:

```python
async def ensure_open(db: AsyncSession, provider: str) -> None:
    """Refuse a new payment in a kassa that is in maintenance or off.

    Raises:
        ConflictError: ``provider_maintenance`` or ``provider_disabled``.
    """
    status = (await read_kassa_fees(db)).status(provider)
    if status == "maintenance":
        raise ConflictError("this kassa is under maintenance", code="provider_maintenance")
    if status == "off":
        raise ConflictError("this kassa is switched off", code="provider_disabled")
```

Call it in `create_topup` before `_gateway(provider)` (not on a replay) and in the order pay
path before `get_gateway(provider)` (`orders/paying.py`; `wallet` is never gated). `/providers`
returns `ProviderOut(slug, fee_pct, status)` for `available_providers()` + `p2p` when its
gateway exists (Task 4), skipping `off`. The admin save keeps the whole document; the audit
payload adds the changed statuses.

```js
export default {
  async fetch(request, env) {
    const given = request.headers.get("X-Telegram-Bot-Api-Secret-Token") ?? "";
    if (request.method !== "POST" || !(await same(given, env.RELAY_SECRET))) {
      return new Response("forbidden", { status: 401 });
    }
    const body = await request.text();
    const send = (url, secret) =>
      fetch(url, {
        method: "POST",
        headers: { "content-type": "application/json", "X-Telegram-Bot-Api-Secret-Token": secret },
        body,
      }).then(
        (r) => r.ok,
        () => false,
      );
    const [a, b] = await Promise.all([
      send(env.YUPAY_URL, env.YUPAY_SECRET),
      send(env.CSMARKET_URL, env.CSMARKET_SECRET),
    ]);
    // Telegram retries anything but 2xx; both sides dedupe by message id.
    return a && b ? new Response("ok") : new Response("retry", { status: 502 });
  },
};
```
