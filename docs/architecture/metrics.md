# Domain metrics

Every domain Prometheus counter is declared in `apps/api/src/csmarket/core/metrics.py` and
listed here, one row per metric (`AGENTS.md` § 5). A new metric lands in the same change as
its first increment. HTTP rate and latency come from `prometheus_fastapi_instrumentator`
(`http_requests_total`, `http_request_duration_seconds`) and are not repeated here.

Two rules (the module docstring has the reasoning):

1. **Labels are bounded and never about a person.** No Steam ID, email, IP, trade-link token,
   order or user id as a label value. Label types are `Literal`, and a helper that takes a
   string collapses an unknown value to `"other"` so a bug cannot mint a new series.
2. **Recording never fails a request.** Every increment is wrapped; a broken registry logs one
   warning and drops the data point.

Scraped over the internal network only: `api:8000/metrics`, `worker:9101/metrics` and
`scheduler:9102/metrics` (`prometheus.yml` jobs `api`, `worker`, `scheduler`; the two ports are
`CSMARKET_WORKER_METRICS_PORT` / `CSMARKET_SCHEDULER_METRICS_PORT` and are not published). Caddy
answers 404 for `/metrics` on the public host. Every process registers every metric of
`core/metrics.py`; counters are incremented where the work happens (buys and refunds in the
worker, sweeps in the scheduler, kassa rejections in the API) and the gauges below are set only
by the scheduler.

All gauge alerts select `job="scheduler"` (the API and the worker expose the same names unset).
`WorkerDown` / `SchedulerDown` (`up{job=...} == 0` for 2 min, page) cover the two processes.

**Counters start at 0.** `core/metrics.py` pre-creates every enumerated label combination of the
refund, attention, buy, Waxpeer-call, Skinslink-call and kassa-rejection counters at import, so a series is
exported at 0 from the start and its first increment is a 0 -> 1 step. A child created by its
first `.inc()` would appear already at 1 and `increase()` of it is 0: the first refund or audit
divergence after a restart would never alert. A test asserts the zero series.

The rules are unit-tested with promtool (`infra/prometheus/tests/orders_test.yml`, and
`api_test.yml` for the latency split between our own routes and the Waxpeer-bound ones, and
`sales_test.yml` for `SalePayoutsOverdue`):

```bash
docker run --rm -v "$PWD/infra/prometheus:/p" --entrypoint promtool \
  prom/prometheus test rules /p/tests/orders_test.yml /p/tests/api_test.yml /p/tests/sales_test.yml
```
